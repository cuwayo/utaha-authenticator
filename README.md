# Utaha Authenticator

A free, open-source, offline-first two-factor authentication app for Android and
iOS, built with Flutter and Material You.

**Your codes never leave your device.** The app requests no network permission at
all — not "does not use the network", but *cannot*, because the permission is
explicitly removed at build time and the build fails if anything reintroduces it.

---

## Features

**Codes**
- TOTP (RFC 6238) and HOTP (RFC 4226), implemented directly and proven against
  the published RFC test vectors.
- SHA-1, SHA-256 and SHA-512. Six, seven or eight digits. Configurable period.
- A countdown ring that turns to the error colour in the last five seconds.
- Tap to copy, with the clipboard cleared again automatically. The clear is
  skipped if you have copied something else in the meantime.
- Optional tap-to-reveal, so codes stay covered until you ask for them.

**Adding accounts**
- Scan a QR code with the camera.
- Import a QR code from a screenshot.
- Type a key in by hand, with clear validation that names the problem.

**Managing accounts**
- Search, pin to the top, drag to reorder, delete with undo.
- Letter avatars coloured deterministically per service.

**Import and export**
- Import your whole Google Authenticator export in one go, with a preview before
  anything is written.
- Encrypted `.utaha` backups: Argon2id + AES-256-GCM.
- A plain-text `otpauth://` export for tools that need it, behind a warning that
  says exactly how unsafe it is.

**Security**
- Secrets in the platform keystore (Android Keystore / iOS Keychain), never in a
  file or preference.
- App lock with biometrics or device credential, with a configurable grace period.
- Screenshots, screen recording and the app-switcher thumbnail blocked.
- Android backup and device transfer disabled outright.

**Look and feel**
- Material 3 with wallpaper-based dynamic colour, falling back to a deep violet.
- Light, dark, and a true-black AMOLED mode.
- Adaptive navigation: bottom bar on phones, navigation rail on tablets and
  foldables.
- Screen-reader support: each account announces itself as one coherent row, with
  codes spelled out digit by digit.

## Install

No release build is published yet. To build it yourself, see below.

## Building

Requires Flutter 3.47.7 or later and JDK 17.

```bash
flutter pub get
flutter run
```

To produce a release build:

```bash
# Optional but required for a publishable build — see android/key.properties.example
cp android/key.properties.example android/key.properties
# ...then fill it in

flutter build appbundle --release   # for Google Play
flutter build apk --release         # for direct install
```

Without `android/key.properties` the release build falls back to the debug key
and warns. That is fine locally and **never** for a published build.

### Release obfuscation

Dart code is not obfuscated by default. To enable it, and to get readable
symbolicated stack traces, build with:

```bash
flutter build appbundle --release \
  --obfuscate \
  --split-debug-info=build/symbols
```

Keep the symbols directory — without it, crash reports from that build are
unreadable. Add `build/symbols` to your own backup.

```bash
tool/generate_icons.sh path/to/icon.png .
```

### Regenerating the migration test vectors

The Google Authenticator import parser is tested against real protobuf wire bytes
generated by `protoc`:

```bash
python3 tool/generate_migration_vectors.py
```

### Adding localisation keys

```bash
python3 tool/add_arb_keys.py lib/l10n/app_en.arb keys.json
```

The helper exists because hand-editing the ARB repeatedly produced invalid JSON.

## Architecture

```
lib/
  app/        app shell, router, providers
  core/       theme, constants, errors, utils, platform ports
  data/       drift database, keystore, repository implementations
  domain/     PURE DART — OTP, otpauth, migration, backup, models, services
  features/   accounts, scan, backup, settings, lock, onboarding, about
```

**The `domain` layer depends on nothing but Dart and `cryptography`.** It has no
Flutter import, which is why the OTP implementation, the URI parser, the
migration parser and the backup codec are all unit-tested without a widget
binding.

`features → domain ← data`: the UI depends on domain interfaces, and the data
layer implements them.

State management is Riverpod 3 with code generation. Routing is `go_router`.

### Two design decisions worth knowing

**`Account` deliberately holds no secret.** The secret lives only in the keystore,
addressed by `Account.id`. This makes it structurally impossible for a log line,
a JSON dump or a crash report to carry a secret, because the model has nothing to
leak.

**Metadata and secrets are two stores with one owner.** `AccountService`
coordinates them and defines the failure behaviour: adding writes the secret
first so no account can appear without a key; deleting removes the metadata first
so the account disappears even if the keystore call fails.

## Status

Complete and **run on a real device for the first time** on 2026-10-14 (Redmi
Note 5A, Android 16). Full evidence in `docs/DEVICE_TEST.md`.

| Verified on a device | Verified by tests only |
|---|---|
| Launches, no crashes | Camera scanning |
| `FLAG_SECURE` blocks screen capture | The unlock path succeeding |
| A real TOTP code matches an independent RFC 6238 computation | Clipboard contents |
| The secret is in the keystore, not on disk | Backup export and restore |
| The device-credential prompt appears | Google Authenticator import |
| The lock refuses to enable without authentication | Argon2id timing on a phone |
| Accessibility labels and digit-by-digit codes | |

**Camera scanning is the largest untested surface.** The permission prompt appears
and was granted, but no QR code has actually been scanned.

**Keep an independent backup of your 2FA secrets** until you have tested the flows
you depend on.

### Known gaps

- **The app icon is third-party character artwork**, not an original mark, and is
  excluded from the MIT licence. It must be replaced or licensed before any public
  release. The Android 13+ themed icon renders as a plain disc, because
  full-colour illustration has no silhouette.
- **iOS screen-capture blocking is not implemented.** The Android approach has no
  direct equivalent; calls are no-ops there.
- **No localisation beyond English.** The app is localisation-ready — every string
  is in `app_en.arb` — but no translations exist, so RTL behaviour is untested.
- **"Smooth, subtle motion" is partial.** The page indicator and the reorder proxy
  animate; the add/edit container transforms were not built.
- **Restore de-duplicates by id only**, so restoring onto a device that already
  has the same accounts under different ids will duplicate them.
- **`pruneOrphanedSecrets` is implemented and tested but not called at startup.**
